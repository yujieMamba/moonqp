# Solver design and supported semantics

## Problem contract

A problem consists of a finite symmetric numerically positive-semidefinite matrix `P`, vector `q`, finite matrix `A`, and one lower/upper bound pair per row. It minimizes `0.5 * xᵀ P x + qᵀx` subject to `lower ≤ Ax ≤ upper`. Bounds may be unbounded on one side using negative infinity in `lower` or positive infinity in `upper`; NaN and the opposite-signed infinities are invalid. Dimension, finite-value, symmetry, convexity and bound-order checks happen before iteration. Equality constraints use identical finite lower and upper bounds. `QpProblem::constraint_values_at(x)` evaluates each row of `A x` in the model's constraint-row order and returns a fresh array, so callers cannot mutate the model through the result. It returns `None` for invalid model data, a vector-length mismatch, non-finite candidate values, or a non-finite row dot product (including multiplication or accumulation overflow). Zero constraint rows produce `Some([])`.

## Dense numeric value API

`DenseMatrix` and `DenseVector` constructors copy and validate finite inputs. Their read methods return values or copies, and arithmetic methods return new values rather than mutating operands. Shape mismatch, invalid indices, non-finite input, or non-finite arithmetic is reported as `None` where an operation can fail. LU uses scaled partial pivoting with a caller-configurable relative pivot threshold; Cholesky accepts only numerically symmetric positive-definite matrices. These general dense kernels are independently exposed from the QP model API and have no sparse backend. `DenseLuFactor::solve_many(rhs)` and `CholeskyFactor::solve_many(rhs)` interpret each column of `rhs` as an independent right-hand side and return a solution matrix with the same row/column shape. They reuse the stored factorization for every column; use them after factoring once when solving a batch of systems with the same coefficient matrix. A row-count mismatch or any non-finite intermediate/solution (including arithmetic overflow) returns `None`. A correctly shaped zero-column matrix returns a same-shaped zero-column result.
## Solver approach

The dense ADMM splitting uses `z = Ax` and projects each row onto its permitted interval. For each call, the solver forms and Cholesky-factorizes `P + rho AᵀA + sigma I`, then reuses that factor within the iteration. `sigma` must be positive, so the x-update remains positive definite even when `P` is singular positive semidefinite.

The solver checks interval feasibility and KKT stationarity using absolute-plus-relative tolerances. The relative primal tolerance is scaled by the largest absolute component of `Ax` or its interval projection `z`, not by the bound values; a very large but loose finite bound therefore cannot mask a violation of the opposite bound. With no constraint rows, the primal scale and residual are zero. It exposes the objective, row-constraint dual multipliers (negative at active lower bounds, positive at active upper bounds), primal feasibility residual, ADMM dual residual, stationarity residual, iteration count and typed status. The status `IterationLimit` means the configured budget expired; it does not prove infeasibility. Callers may provide finite primal and dual initial vectors for repeated nearby solves. The optional `initial_y` must contain one finite multiplier per constraint row and is rejected as `InvalidProblem` with zero iterations otherwise. It initializes the solver's unscaled row-multiplier vector using the existing sign convention (negative at active lower bounds, positive at active upper bounds); the associated initial projection is formed consistently from `Ax + y/rho`. When omitted, the existing zero-dual initialization and cold-start path remain unchanged. A warm start is not checked for consistency with a changed model and does not guarantee fewer iterations. Model updates and infeasibility certificates are not provided.

## Numerical acceptance

The convexity check uses Jacobi diagonalization with a scale-relative computed-eigenvalue cutoff of `1e-14 * max_abs(P)` and an off-diagonal rotation cutoff of `1e-15 * max_abs(P)`. The eigenvalue band is intended only to absorb floating-point roundoff (including a slightly negative computed eigenvalue for a rounded rank-deficient PSD matrix); it is not a mathematical PSD certificate. A negative eigenvalue inside that band is numerically treated as zero, so inputs with curvature below the resolution of the tolerance cannot be distinguished from roundoff. Material negative curvature such as `-5e-11` relative to a unit-scale diagonal is rejected, independently of uniform matrix scaling. The all-zero and rank-deficient PSD cases remain supported.

Tests cover analytically solvable unconstrained, equality, interval, one-sided-bound and singular-PSD cases, zero constraint rows, malformed dimensions, nonsymmetric/indefinite `P`, invalid bounds and budget exhaustion. Tests independently recompute representative objective, feasibility and stationarity values instead of relying only on solver diagnostics. Tolerance behavior and ill-conditioning remain explicit limitations; no sparse-scale or OSQP-performance guarantee is made.
